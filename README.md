# Untrained similarity floors of protein-ligand affinity networks

Code, analysis plan and result tables for the study of the representational similarity of untrained
geometric networks of protein-ligand complexes (random-network sweep, input-geometry kernels,
input ablations, probe panel).

## Layout

| Path | Content |
|---|---|
| `findings/` | analysis scripts (`a1` sweep, `a3` floor regression, `a4` ablations, `a5_a7` real untrained networks, `b0`/`b_probe_panel` probes, `c3` output agreement) and shared helpers |
| `findings/plan/` | analysis plan (`findings_plan.yaml`) |
| `findings/tests/` | tests and an end-to-end run on synthetic data |
| `findings_out/` | result tables (`res_*.tsv`), `targets_meta.json` |
| `logs/` | stdout of the two run stages |
| `paper_analysis/` | `analysis.py` and `analysis2.py` recompute every number, table and figure of the paper from `findings_out/` |

## Running

`lock_freeze.py lock` pins the plan and `lock_freeze.py freeze` pins the analysis code. Result-producing
scripts abort if the plan or the code differs from the lock or freeze (both files are created by these commands). Run order:

```
python3 findings/lock_freeze.py lock
python3 findings/build_graphs.py && python3 findings/input_kernels.py && python3 findings/b0_make_targets.py
python3 findings/lock_freeze.py freeze
for s in a1_floor_sweep a4_ablation a3_floor_model a5_a7_real_untrained b_probe_panel c3_output_agreement; do
  python3 findings/$s.py; done
```

All scripts read `PROJECT_ROOT` (default: current directory).

## Inputs that are not in this repository

* PDBbind v2020 structures (`PDBbind_2020/`) and the LP-PDBBind split, obtained from their original sources
  under their own terms of use. Nothing derived from PDBbind at the level of single complexes is committed
  (`targets.tsv`, `kernels.npz` are regenerated by `b0_make_targets.py` and `input_kernels.py`).
* Embeddings of the trained and untrained reference models (`data/embeddings/`), the split, cluster and
  covariate tables (`data/`), produced by the reference-model pipeline below. Raw per-complex docking output is in
  `data/docking_results.tsv` (identifiers and numeric results only).

## Reference-model pipeline

* `src/` holds the similarity library (`alignlib.py`), configuration locking (`prereg.py`), seeds and embedding helpers.
* `config/` holds the frozen reference-model configuration and its lock file (Colab paths in `config.yaml` are to be edited).
* `gpu_runs/` builds clusters, covariates and input kernels and runs the second-seed and untrained-initialisation extractions.
* `notebooks/` trains and extracts the reference models: `notebook_2a_egnn_distancegnn.ipynb` (EGNN and Distance-GNN, model classes in `src/embed_utils.py`) and the voxel-CNN notebooks 2b and 2c (`.py` and `.ipynb`).
* `docking/` holds the docking preparation (`dockprep.py`, `prepladder.py`) and runner (`dockrun.py`).

Not included: the raw embeddings and checkpoints (large; the docking queue is the `pid` column of `data/docking_results.tsv`).

## Docking agreement and subspace projection

* `docking/make_vina_results.py` turns `data/docking_results.tsv` into `logs/vina_results.json`, and
  `docking/docking_agreement.py` computes the partial Spearman correlation of each model's predicted affinity with the
  negated Vina score given ligand heavy-atom count (cluster bootstrap), plus the Vina score's correlation with measured
  affinity and size, into `logs/docking_agreement.json`. The statistical helpers were checked against a direct
  rank-residual calculation on synthetic data. The full script needs the stored embeddings and checkpoints and was not
  re-run here.
* `gpu_runs/run_residualization_r2.py` projects the ligand-fingerprint and pocket amino-acid-composition reference
  directions out of each embedding and records the CKA change and the variance share. Its output is
  `results/residualization_r2.json`, which holds the numbers reported in the paper (for example 100 fingerprint
  directions, CKA change 0.26 to 0.35, and 17 composition directions, change at most 0.026).

## Recomputing the paper's numbers

```
python3 findings/b0_make_targets.py                      # needs PDBbind, writes findings_out/targets.tsv
REFERENCE_LOGS=<dir with h1_results.json, performance_table.json, embedding_health_2a.json> \
  python3 -I paper_analysis/analysis.py
python3 -I paper_analysis/analysis2.py
```

Outputs go to `paper_analysis/generated/` (override with `PAPER_OUT`). With the shipped result tables these
scripts reproduce the paper's `numbers.json`, `numbers2.json` and tables.

## Environment

See `requirements.txt`. The sweep forward passes are NumPy float32 re-implementations, so the exact random
weights can depend on the NumPy version.

## Docking

`docking/dockrun.py` is the docking runner (frozen preparation ladder, AutoDock Vina 1.2.7, crystal-referenced
RMSD, one result file per complex). It imports `dockprep.py`, `prepladder.py` and `src/prereg.py`, which are in the repository, and a docking queue table (the list of complexes to dock).
